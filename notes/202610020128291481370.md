Ktor 3.6.0's tcp.tls { addCertificateChain(...) } never presents an EC client certificate: a server that asks for one sees none and answers 60 (no error on the client). Its CertificateType only lists RSA and DSS, no ecdsa_sign. This was found by generating EC P-256 identities, which silently failed; switching the key type to RSA made ClientCertificateTransportTest pass. The app no longer generates identities, but the limit now shows up on import: JdkIdentityCodec rejects EC and other non-RSA certificates or keys with 'Only RSA identities are supported' rather than importing something that can't log in. Unverified: whether Lagrange identities are RSA; check with a real export. Revisit if a later Ktor supports EC.
