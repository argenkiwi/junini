Socket.tls(context) launches long-lived TLS reader/writer coroutines as children of the Job in the context you pass. If you pass the enclosing coroutineContext (for example inside withTimeout), the scope waits for those children after the body returns and never completes, so every request times out even though the response has been read. Fix in GeminiTransport.jvm.kt: pass Dispatchers.IO + a dedicated Job() and cancel that Job in finally. Reproduced by comparing a probe that passed Dispatchers.IO (1.5 s) with the original code (30 s timeout).
