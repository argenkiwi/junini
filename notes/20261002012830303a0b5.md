The app doesn't generate identities. Users import what Lagrange uses: a .crt and a .key, or one .pem with both (the UI asks for a second file when the first lacks the certificate or the key). Pem.kt (commonMain, pure Kotlin) parses blocks and tells the UI which part is missing; JdkIdentityCodec (jvmShared, JDK only, no BouncyCastle) builds the identity, wraps PKCS#1 keys as PKCS#8, rejects encrypted and non-RSA keys, and checks that the key matches a certificate (the matching one becomes the leaf). Name = certificate CN. id = first 16 hex chars of the SHA-256, which also rejects duplicates. FileIdentityStore keeps an index, an assignments file (host port id) and keys/<id>.crt plus keys/<id>.key, unencrypted, with the key file owner-only where POSIX permissions exist, so it is only as private as app storage. Export is one combined PEM and warns that it holds the private key. Assignment is per host:port only, not per path as the Gemini spec allows. The transport asks IdentityStore.credentialsFor(host, port) on each fetch. IdentityManager and IdentityFiles are injected through App() like the known-hosts store; iOS and Web pass null, which hides the Identities menu item. Status 60/61/62 become PageState.ClientCertificateRequired, excluded from the back stack like CertificateChanged.
