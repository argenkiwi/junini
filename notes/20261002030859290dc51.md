BrowserViewModel.reload() reloads state.currentUrl, not the URL field the user may have edited. It sets BrowserState.isRefreshing, which the screen uses to show the pull indicator instead of the LinearProgressIndicator; every path that cancels or finishes a load (goBack, goForward, cancel, load completion) must clear it or the spinner sticks. The back stack is untouched: load() skips the push when refreshing, so even a reload that redirects replaces the page instead of leaving it behind. With no page loaded yet, reload() opens the typed URL, so F5/Ctrl+R still work on a fresh start. PullToRefreshBox stays in the composition always (switching branches would reset the list scroll position); for Idle, Input and the identities screen it just shows no indicator and ignores the pull. MessageView is verticalScroll-able so error pages can be pulled too.
