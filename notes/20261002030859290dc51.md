BrowserViewModel.reload() reloads state.currentUrl, not the URL field the user may have edited. It sets BrowserState.isRefreshing, which the screen uses to show the pull indicator instead of the LinearProgressIndicator; every path that cancels or finishes a load (goBack, goForward, cancel, load completion) must clear it or the spinner sticks. The back stack is untouched because load() only pushes an entry when previousUrl != finalUrl. PullToRefreshBox is skipped for Idle, Input and the identities screen, and MessageView is verticalScroll-able so error pages can be pulled too. F5/Ctrl+R on desktop call reload() as well.
