Gemini needs TLS over raw TCP (port 1965). In Ktor 3.6.0, ktor-network-tls on non-JVM targets is a stub: openTLSSession throws "TLS sessions are not supported on Native platform." Browsers cannot open raw TCP sockets at all. So the real transport lives in a custom jvmShared source set (jvm + android, declared via applyDefaultHierarchyTemplate with withCompilations { platformType == androidJvm }, which works with the AGP-9 android KMP plugin). iosMain/webMain return UnsupportedGeminiTransport. Options for later: NWConnection cinterop on iOS, a WebSocket/HTTP proxy for web. Ktor JVM TLS is its own TLS 1.2 implementation, so servers that only speak TLS 1.3 will fail. Every capsule tested in Oct 2026 (geminiprotocol.net, kennedy, station, bbs.geminispace, skyjake.fi) works.
